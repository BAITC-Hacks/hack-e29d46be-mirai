# Сквозной транзит: совместимость сумм и дат

Основное окно — **1–2 календарных дня после входящего перевода**. В исходных данных
нет времени суток, поэтому порядок внутри дня неизвестен.

Для каждого узла отдельно агрегируем входящие и исходящие суммы по дню. Исходящие
обрабатываются по возрастанию даты. Им сопоставляется доступная входящая сумма,
начиная с самой ранней в окне (FIFO); использованная сумма вычитается. Просроченные
входящие удаляются. Один тенге не может быть повторно использован в сопоставлении
для того же узла. Самопереводы исключены.

`fast_transit_share = matched_kzt / observed_incoming_kzt`, диапазон [0, 1],
при отсутствии входящих — 0. `fast_transit = share >= 0.80 AND NOT is_seed`.
Порог 80% — объяснимая эвристика «большая часть прошла дальше», не обученная оценка.
Для seed числовая доля остаётся доступной, но флаг не ставится;
`transit_seed_caveat` предупреждает о неполных входящих.

Отдельно считаем `same_day_transit_share_upper_bound` тем же алгоритмом для окна
**0–2 дня**. Это верхняя оценка при допущении, что входящие в тот же день были раньше
исходящих. Она не используется в основном флаге.

Пример: входящие 100 KZT 1 июля и 100 KZT 2 июля, исходящие 160 KZT 3 июля →
доля 0.8. Один исходящий 100 KZT нельзя зачесть по 100 KZT каждому из двух входящих.

Знаменатель включает все наблюдаемые входящие. `transit_observation_complete_share`
показывает долю входящих, для которых до последней даты датасета остаётся полное
двухдневное окно. Низкая доля предупреждает о занижении transit из-за конца периода.
Последняя дата транзакций — наблюдаемый горизонт, а не гарантия полноты выгрузки.

Это совместимость денежных потоков по времени и объёму, не доказательство того,
что пересланы именно полученные деньги: начальные остатки и внешние переводы неизвестны.
Баланс клиента не восстанавливается. На исходных данных основной флаг имеют 72 узла.
