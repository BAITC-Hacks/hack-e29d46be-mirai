# Устойчивость при удалении top-N

Используем направленный граф со **всеми** узлами из nodes, включая изолированные.
Устойчивость описывается слабо связными компонентами: направление игнорируется
только при проверке связности. Это структурная связанность, не достижимость
денег по направлению и не прогноз поведения клиентов после удаления узла.

Порядок удаления фиксируется один раз для исходного графа:

1. Полный конечный числовой столбец `nodes.priority_score`, если передан.
2. Иначе полный `nodes.betweenness`, если передан.
3. Иначе directed **unweighted** betweenness: до 128 исходных вершин, seed=42.
   Для ≤128 узлов используется точный расчёт. Сумма перевода не превращается в длину пути.

При равном значении первым идёт меньший gid. Для каждого сценария явно сохраняем
`ranking_metric` и точный список `removed_gids` (строки). Пересчёта ранга после каждого
удаления нет. Это сравнение статических сценариев, не оптимизация атаки на сеть.

Возвращаем базовую строку N=0 и сценарии N=5/10/20. На маленьком графе удаляем
не больше имеющихся узлов, `actual_removed_n` сообщает фактическое число.

| Поле | Определение |
|---|---|
| `largest_component_nodes` | Число оставшихся узлов в крупнейшей слабой компоненте |
| `largest_component_share` | Это число / число **оставшихся** узлов |
| `largest_component_original_share` | Это число / исходное число узлов |
| `n_components` | Число слабых компонент среди оставшихся, включая одиночки |
| `observed_flow_removed_share` | Доля суммы наблюдаемых рёбер, исчезнувших с удалёнными узлами |

При пустом знаменателе доля равна 0. Рёбра между двумя удалёнными узлами не считаются
дважды. Доля удалённого оборота описывает исторические рёбра, не «предотвращённый ущерб».
Доля крупнейшей компоненты среди оставшихся не обязана убывать; для сравнения
с исходной сетью смотрите также `largest_component_original_share`.

Сырые nodes не содержат priority_score, поэтому самостоятельный запуск использует
приближённый betweenness и честно указывает это в результате. Полный пайплайн повторно
вызывает `compute_resilience` после расчёта priority и экспортирует сценарии по итоговому рейтингу.

Исходный граф с fallback (приближённые значения):

| Удалено | Осталось | Крупнейшая компонента | Доля от оставшихся | Компонент |
|---|---|---|---|---|
| 0 | 2 248 | 1 877 | 0.8350 | 35 |
| 5 | 2 243 | 1 821 | 0.8119 | 77 |
| 10 | 2 238 | 1 747 | 0.7806 | 132 |
| 20 | 2 228 | 1 372 | 0.6158 | 348 |

35 исходных компонент = 16 в графе рёбер + 19 изолированных seed. Это объясняет
расхождение со стартовым описанием, которое считает компоненты только рёбер.
