# Повторяющиеся маршруты A → B → C

Три разных узла, оба направленных ребра присутствуют в графе. Для каждого ребра
нужно не меньше двух наблюдаемых транзакций. Этого недостаточно: проверяем даты.
Каждому B→C сопоставляем самый ранний ещё не использованный A→B за **1–2 дня до него**.
Просроченные входящие пропускаем. Один перевод на каждом ребре используется
не более одного раза **для данного маршрута**. Нужно ≥2 таких последовательностей.
Одинаковая дата внутри одной пары исключается, поскольку время суток неизвестно.
Несколько разных транзакций на одном и том же наборе дат могут давать несколько
последовательностей: это счёт транзакций, не число разных дней.

`extras.repeated_routes`: `gids` (три строки), `occurrences`, `window_days=2`.
`repeated_route_count`: число найденных маршрутов, содержащих узел, не сумма их повторений.
При одинаковых входах порядок результата детерминирован по gid.

Это временно совместимые **кандидаты** на повторение маршрута, не трассировка денег:
суммы не сопоставляются и один перевод может поддерживать разные альтернативные
маршруты. Нельзя складывать их объёмы, трактовать occurrences как уникальные потоки
по всей сети или утверждать, что C получил деньги именно A. Для сопоставления
объёмов отдельно используется fast_transit_share у B. Конец месяца обрезает маршруты.

Бюджеты: 50 000 кандидатов, 1 000 результатов, 5 секунд поиска. При ограничении
`repeated_routes_complete=False` и предупреждение; отсутствие маршрута не доказано.
На исходных данных: 118 маршрутов, максимум 7 последовательностей, 4 541 кандидата,
поиск полный. Ни один gid не зафиксирован в алгоритме.
