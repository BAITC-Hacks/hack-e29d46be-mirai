# Кейс: «Граф денег» — сжатое ТЗ

> Полный текст — PDF у организаторов. Здесь всё, что нужно агентам для работы.

## Суть
AML-аналитику банка известны 81 «курьер» (seed-клиенты, наркотрафик). По их исходящим переводам на 4 колена
собран граф: **2 248 узлов, 3 119 рёбер, 4 840 транзакций**, июль 2026.
Инструмент должен ответить: **«кого из 2 248 клиентов смотреть первым и почему»**.

Формат: 5 часов, команда. Данные и стартовый код (`starter/`) выдают в начале. Внешние источники запрещены.

## Вход (`data/`)
| Файл | Строк | Поля |
|---|---|---|
| `edges.parquet` | 3 119 | `src, dst, sum_kzt, n_tx, depth` (агрегат за период) |
| `nodes.parquet` | 2 248 | `gid, depth` (минимальное колено), `is_seed` |
| `transactions.parquet` | 4 840 | `src, dst, date, sum_kzt` |

Данные уже в репо: `data/` (описание — `data/README.md`, схема совпадает с таблицей выше).
Стартовый код: `starter/starter.py` — загрузка, проверка консистентности, граф, базовые метрики
(`in_deg, out_deg, in_kzt, out_kzt, in_tx, out_tx, pagerank, pass_through, truncated_by_depth`), пустые выгрузки.
Обязательно прочитать `starter/README.md` — там 4 ловушки (+ «суммы и количество переводов — разные сигналы»,
«граф направленный — не используйте ненаправленные метрики без оговорки»).

## Выход (фиксированная схема — см. `docs/CONTRACTS.md`)
1. `nodes_roles.csv` — все 2 248 узлов: `gid, role, role_score, cluster_id, priority_score, evidence (≤200 символов)`
2. `clusters.csv` — `cluster_id, n_nodes, n_seed, sum_kzt_internal, top_gids, hypothesis`
3. `top_nodes.csv` — ≥ 20 узлов: `rank, gid, role, priority_score, why`
4. Экран: схема сети с направлением потоков, подсветка ролей/кластеров, поиск по gid.

## Словарь ролей (минимум, можно расширять с документацией)
`consolidator` (собирает от многих) · `transit` (пропускает дальше, не удерживая) · `distributor` (веер на многих) ·
`terminal` (деньги приходят и остаются) · `coordinator` (кандидат в организаторы) · `peripheral` (признаков нет)

## Must have (без них решение не засчитано)
1. **Один запуск** от сырых parquet до 3 CSV, < 5 минут, на чистой машине, без ручных шагов.
2. **Роль + role_score + evidence у каждого** из 2 248 узлов.
3. **Критерии ролей задокументированы** (правило/метрика + порог). Жюри называет 3 gid → за минуту объясняем.
4. **Кластеризация**: clusters.csv, cluster_id у каждого узла.
5. **Топ-лист ≥ 20 + визуализация**: жюри называет gid → находим на схеме и показываем связи.

## Ловушки в данных (их учёт оценивается!)
- **Обрыв на 4-м колене**: 444 узла с depth=4 и нулевыми исходящими — артефакт обхода, НЕ «деньги осели». Наивное `out_degree=0 ⇒ terminal` даст 444 ложных стока.
- Видны только исходящие переводы → полный баланс узла посчитать нельзя.
- У seed входящие занижены → «отдал/получил» у seed некорректно; 354 узла отдают больше, чем получили.
- Порог 5 000 KZT — дробление ниже порога невидимо.
- 19 из 81 seed нет в рёбрах, 12 только как получатели, 31 seed без исходящих.
- 16 слабосвязных компонент: 1 877 узлов (46 seed), 270 (1 seed), 14 мелких (2–17).
- Нет атрибутов клиентов, нет ground truth → оценивают обоснованность, не accuracy.

Подсказка организаторов: есть узлы с входящими от 8–24 разных плательщиков, веерные на 60–116 получателей,
72 узла с коэффициентом пропуска 0.8–1.2, Louvain даёт ~8 устойчивых сообществ с >1 seed.

## Опционально (доп. баллы)
- Отделение настоящих terminal от обрезанных 4-м коленом, с обоснованием метода
- Временные паттерны: сквозной транзит за 1–2 дня, всплески, синхронные переводы нескольких плательщиков в один день
- Повторяющиеся маршруты A→B→C и циклы (деньги возвращаются)
- Аномалии: дробление сумм, нетипичные профили относительно колена
- Устойчивость сети: что будет при изъятии топ-N узлов
- **AI-ассистент аналитика**: вопрос на естественном языке → ответ по графу со ссылками на узлы
- **Автогенерация карточки узла**: роль, потоки, связи, на что обратить внимание
- Оценка полноты: каких данных не хватает, какой запрос сделать следующим

## Нельзя
- Хардкодить списки gid под «правильный ответ»
- «Чёрный ящик» без объяснимых правил
- Выдумывать атрибуты клиентов (пол, возраст, доход…)
- Требовать облако/GPU/платные сервисы для воспроизведения (LLM API — только как опция)

## Обязательно учесть
- **Осторожность формулировок**: «признаки консолидации», а не «организатор преступной группы». Выводы — гипотезы.
- Всё локально на ноутбуке. Интернет — только для LLM API.
- В README раздел: что изменится при росте графа до ~1 млн узлов (текстом).
