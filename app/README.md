# Интерфейс Mirai (задачи Нурай #7–#9)

Тёмная тема, русский интерфейс, три колонки для ноутбука. При открытии —
100 узлов с наибольшим `priority_score` и их непосредственные соседи.
Координаты берутся из `graph.json`; браузер не рассчитывает раскладку.
Cytoscape.js 3.30.4 хранится локально, интернет для интерфейса не нужен.

## Запуск

Общий запуск после интеграции команды: `python run.py`.
Для независимой проверки интерфейса из корня репозитория:

```sh
python -m pip install fastapi uvicorn
python -m uvicorn app.server:app --host 127.0.0.1 --port 8000
```

Открыть http://localhost:8000. Сервер импортируется как `app.server:app`.
Нужен `outputs/graph.json` либо `shared/sample_graph.json` по CONTRACTS.md §2.
Без обоих файлов интерфейс покажет сообщение с кнопкой повторной загрузки,
API вернёт 503. Запуск не генерирует фиктивные данные.
Появление/обновление выхода пайплайна подхватывается без перезапуска сервера;
для обновления экрана нажать ↻. Пути считаются от репозитория, не от cwd.

## Проверка в браузере

1. Введите полный gid, нажмите Enter: фокус на клиенте и его связях, карточка справа.
   Поиск работает и для узлов вне топ-100. Частичный gid показывает до 20 результатов;
   точное совпадение идёт первым. Стрелки вверх/вниз и Enter выбирают результат.
2. Переключите «Весь граф» / «Эго-сеть». Эго-сеть требует выбранного клиента.
   Выберите кластер для подсветки; выбор клиента снимает подсветку кластера.
3. В карточке проверьте метрики, входящие/исходящие связи (раскрываются), флаги,
   предупреждения для seed и четвёртого колена. Нажмите на соседний gid.
4. Нажмите «Составить AI-карточку». Без модуля assistant будет шаблон по данным.
5. На вкладке «Ассистент» отправьте вопрос. `assistant.ask` подключается автоматически;
   при отсутствии/ошибке/таймауте — понятный fallback. Ссылки только на существующие
   `cited_gids`; клик открывает клиента. Ответы выводятся текстом, не HTML.

Размер и цвет узла обозначают приоритет и роль; ромб — seed. Стрелки показывают
направление, толщина — логарифм суммы. Оценки и evidence приходят от пайплайна:
интерфейс не назначает роли и не изменяет аналитические выводы.

## HTTP

Все пути из CONTRACTS.md §3 реализованы. Уточнение формы ответов:

- `/api/node/{gid}`: `{node, incoming, outgoing, neighbors}`; соседи — объекты узлов.
- `/api/search?q=...`: массив узлов, максимум 20; пустой запрос — пустой массив.
- `/api/top?n=20`: массив `{rank, gid, role, priority_score, why}` из выходного CSV;
  при отсутствии CSV — сортировка графа по приоритету, `why` из `evidence`.
- Все gid в JSON, параметрах функций ассистента и `cited_gids` — строки.
  Это сохраняет 18-значные ID без округления в JavaScript (контракт из PR #15).
- Несуществующий gid: 404; некорректный ввод: 422; недоступный граф: 503.
- Вопрос: 1–4000 символов после проверки на пустоту. Ожидание ассистента: 25 секунд.
  Функции ассистента выполняются в рабочем потоке и получают копию графа.

## Тесты

```sh
python -m pip install pytest httpx
python -m pytest app/tests -q
```

Тесты используют временные файлы и не меняют `data/`, `shared/`, `outputs/`.
Покрыты контракт API, поиск и лимиты, обновление файлов, приоритет выхода над моком,
CSV, пропущенные поля, петля, отсутствующий/ошибающийся assistant, изоляция его данных,
повреждённый граф, 2248 узлов и два 18-значных ID, отличающихся последней цифрой.
Ручная браузерная проверка: 2248 узлов / 3119 рёбер при 1366×768.
API также проверен на настоящем graph.json из PR #15 (роли v0).
Реальный LLM требует интеграции модуля Даниала; fallback проверен без ключей.

Изменения ограничены `app/`. Общие зависимости, `run.py` и аналитический пайплайн
остаются у их владельца. Провайдер LLM и его ключи настраивает модуль `assistant/`.
